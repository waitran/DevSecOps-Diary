Тема: Безопасная настройка Git, работа с файловой системой и правами доступа.
🧠 Суть дня (Теория)
Git Workflow: Локальные изменения сначала добавляются в индекс (git add), затем фиксируются снимком состояния (git commit), и только потом отправляются на удалённый сервер (git push).
SSH vs HTTPS: GitHub отключил аутентификацию по паролю для Git-операций. Профессиональный стандарт — использование SSH-ключей (id_ed25519), где приватный ключ остаётся на машине, а публичный (*.pub) добавляется в аккаунт GitHub.
Права доступа в Linux: Каждый файл имеет владельца (owner), группу (group) и остальных (others). Права делятся на чтение (r=4), запись (w=2) и выполнение (x=1).
Идемпотентность: Свойство операции давать один и тот же результат при многократном применении. Критически важно для скриптов автоматизации (например, mkdir -p не выдаст ошибку, если папка уже существует).

# Генерация безопасного SSH-ключа (Ed25519)
ssh-keygen -t ed25519 -C "your@email.com"

# Просмотр публичного ключа (для копирования в GitHub)
cat ~/.ssh/id_ed25519.pub

# Проверка подключения к GitHub
ssh -T git@github.com

# Смена URL репозитория с HTTPS на SSH
git remote set-url origin git@github.com:USERNAME/REPO.git
git remote -v  # Проверка


# Создание вложенных папок (идемпотентно)
mkdir -p day-001/{labs,notes}

# Создание файла
touch file.txt

# Изменение прав: добавить выполнение для всех
chmod +x script.sh

# Изменение прав в цифровом формате (владелец: rwx=7, группа: r-x=5, остальные: r-x=5)
chmod 755 script.sh

# Закрытие доступа к приватному ключу (только чтение/запись для владельца)
chmod 600 ~/.ssh/id_ed25519


git status       # Проверка состояния файлов
git add .        # Добавить все изменения в индекс
git commit -m "Сообщение"  # Создать коммит
git push origin main       # Отправить изменения на GitHub


🛡️ Security Focus (DevSecOps Mindset)
Никогда не коммить секреты: Файлы .env, secrets/, *.pem, *.key должны быть немедленно добавлены в .gitignore. Один коммит с паролем = компрометация, так как история Git хранится навсегда.
Защита приватных ключей: Приватный SSH-ключ всегда должен иметь права 600 (-rw-------). Если права шире, SSH-клиент откажется его использовать.
Принцип наименьших привилегий (PoLP): Файлам и папкам нужно давать ровно те права, которые необходимы для работы, и не больше. Скрипты не должны запускаться от root без крайней необходимости.
Идемпотентность в безопасности: Скрипты развёртывания должны безопасно отрабатывать многократно. Использование mkdir -p или chmod в скриптах предотвращает сбои и непреднамеренное открытие прав при повторном запуске.
